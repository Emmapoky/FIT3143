----------------------------------------------------------------
SLIDE 2  Architecture  TAABISH  (0:24)
----------------------------------------------------------------
Every charging node is one MPI process. The base station is one more process, the last rank.
The nodes sit in a rows by columns Cartesian grid, so a node only talks to its up, down, left and right neighbours, like a real radio range.
Any node can still report straight to the base station.

----------------------------------------------------------------
SLIDE 3  Inside a node  TAABISH  (0:23)
----------------------------------------------------------------
Inside each node is an OpenMP team of k plus 1 threads.
Thread 0 is the only one that calls MPI, so MPI_THREAD_FUNNELED is enough.
Threads 1 to k are the charging ports. Each one writes only its own slot of the shared array, using atomics, so we need no mutex.

----------------------------------------------------------------
SLIDE 4  Virtual topology  TAABISH  (0:22)
----------------------------------------------------------------
MPI_Comm_split takes the base station out of the grid.
MPI_Cart_create builds the grid with no wrap-around, because an edge node has nobody past it.
MPI_Cart_shift gives each node its four neighbours, and edges return MPI_PROC_NULL, so border nodes need no special case.
Rows equal to 1 gives the line topology.

----------------------------------------------------------------
SLIDE 5  When a node fills up  TAABISH  (0:21)
----------------------------------------------------------------
When a node's free ports hit the threshold, it asks its neighbours.
If one has room, the cars go there and the base station never hears about it.
If every neighbour is full too, the node sends one report.
That report is one derived datatype, 176 bytes.

----------------------------------------------------------------
SLIDE 6  Three node versions  TAABISH  (0:27)
----------------------------------------------------------------
We built three ways to ask.
Version 1 blocks in MPI_Probe, so the node runs no cycles while it waits.
Version 3 uses MPI_Neighbor_allgather every cycle, so it sends 3.16 messages per node per cycle against 1.90, and blocks inside the collective.
Version 2, Isend and Irecv with Testall, never blocks, so we chose it.
Erwyna takes the base station.

----------------------------------------------------------------
SLIDE 7  Base station decision  ERWYNA  (0:29)
----------------------------------------------------------------
The base station is one process with one thread doing all the MPI.
Say node 0 reports and its neighbours are 1 and 3.
If both reported inside the window W, they already cover 2, 4 and 6, so the answer is no nodes nearby.
Otherwise we send all the free nodes two hops away, and widen to three hops, then four, if none are free.

----------------------------------------------------------------
SLIDE 8  Base station versions  ERWYNA  (0:34)
----------------------------------------------------------------
We built three receive loops and hit them with every node reporting.
Version 1, probe plus blocking send, is a serial queue: delay climbs from 1 to 3.5 milliseconds at 64 nodes.
Version 2, one Irecv on any source, is fastest, 0.15 to 0.21 milliseconds.
Version 3, one persistent receive per node drained with MPI_Testsome, is flat at 0.27 to 0.31.
We kept version 3 because it does half the work per report of version 2.

----------------------------------------------------------------
SLIDE 9  Log and shutdown  ERWYNA  (0:18)
----------------------------------------------------------------
Every report is logged with the reporter, its neighbours, the messages and the answer.
For shutdown, the base station sends TERMINATE, waits for every node's ACK, and only then sends SHUTDOWN.
So nothing is still in flight when MPI_Finalize runs.

----------------------------------------------------------------
SLIDE 10  How we measured  ERWYNA  (0:25)
----------------------------------------------------------------
Every message carries its send time, so we get a one way delay for each of the eight message types.
MPI_Wtime is not global on our machines, so we use the system clock.
We ran 32 grid sizes and 32 line sizes, three seeds each on the laptop, then one seed on CAAS across four machines.

----------------------------------------------------------------
SLIDE 11  Task 3a grid size  ERWYNA  (0:26)
----------------------------------------------------------------
Neighbour round trip stays nearly flat, 0.65 to 0.77 milliseconds from 4 to 64 nodes, because a node never has more than four neighbours.
Report round trip only goes from 0.49 to 0.64, so the base station keeps up.
What does grow is termination, because the base station sends one message per node, so that is O of n.

----------------------------------------------------------------
SLIDE 12  Task 3b line topology  TAABISH  (0:26)
----------------------------------------------------------------
For the line we set rows to 1, from 1 by 2 up to 1 by 64.
A node now has at most two neighbours, and the round trip barely changes.
The big difference is traffic: with only two neighbours, both are full more often, so the line sends 2.4 times the reports, 1.47 per node against 0.60.

----------------------------------------------------------------
SLIDE 13  Extra findings  ERWYNA  (0:18)
----------------------------------------------------------------
Two extra experiments.
A longer window W means more answers become none nearby, from 2 to 18 percent.
With no poll sleep the round trip drops to 0.17 milliseconds, but burns 39 CPU seconds against 4 at our 200 microsecond sleep.

----------------------------------------------------------------
SLIDE 14  Limitations and future work  TAABISH  (0:20)
----------------------------------------------------------------
The base station is a single point of failure.
Past 13 nodes our laptop has more processes than cores.
And MPI assumes reliable links, which real radios do not give.
Next we would split the base station by region and run the full sweep on CAAS.
