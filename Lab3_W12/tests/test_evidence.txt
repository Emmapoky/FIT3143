4. Leak check with macOS leaks --atExit (one per rank)
   empty MPI program (MPI_Init_thread + MPI_Finalize only): 78 to 81 leaks per process
   our 1x1 run                                               : 78 to 81 leaks per process (identical)
   our 2x2 run, v1, v2, v3                                   : 119 to 122 per process
   With MallocStackLogging every leak stack that passes through our binary goes through
   main + 68 = MPI_Init_thread (32 of 32). None start in node.c, base_station.c or common.c.
   Raw output: tests/leaks_2x2_v3_raw.txt
   So the remaining "leaks" are Open MPI / PMIx start up allocations, not ours.

5. Bugs found by testing and fixed (kept here because the Q&A may ask)
   a) Base station spun at 100% CPU and never shut down: after the last ACK we stop
      re-posting the ACK receive, and MPI_Test on MPI_REQUEST_NULL returns flag = true
      every time, so phantom ACKs were counted forever. Fixed by testing only non-null.
   b) Negative one way delays: Open MPI on macOS reports MPI_WTIME_IS_GLOBAL = 0 and each
      process's MPI_Wtime has its own zero. Switched send stamps to the system real time
      clock (wsn_now in common.c). Round trips are measured on one clock and never needed it.
   c) Base station v3 answers were ~250 us slow: a persistent send started with MPI_Start
      was only progressed at our next MPI call, one poll sleep later. Added one MPI_Test
      straight after MPI_Start.
